## ストレージ・ファイルシステム方針

### 方針の概要

| 項目 | 決定内容 |
|---|---|
| 優先事項 | **速度優先**（LLM推論のI/O遅延を最小化） |
| 冗長性 | **NAS への定期バックアップ**で担保（RAID構成は採用しない） |
| 初期構成 | **NVMe 2TB × 1本** で LVM 構成 |
| 将来拡張 | 2本目の NVMe 追加時に LVM ボリュームグループを拡張 |

---

### ファイルシステムの選定

| ファイルシステム | 特徴 | 評価 |
|---|---|---|
| **ext4** | Linuxの定番。安定性・互換性が高い | ✅ 推奨（LVMと組み合わせやすい） |
| **xfs** | 大容量ファイルの読み書きに優れる | ✅ 推奨（大型モデルファイルに有利） |
| btrfs | スナップショット・透過圧縮機能あり | △ GGUF等の量子化済みバイナリへの圧縮効果が薄く、速度優先の方針とは相性が悪い |

**→ 採用: `ext4`**（LVMとの組み合わせが枯れており安定。速度・互換性ともに問題なし）

> LLM モデルファイルは 1 モデルあたり数 GB〜数十 GB（例：Llama 3 70B GGUF ≒ 40 GB）。
> btrfs の透過圧縮は量子化済みバイナリへの効果が薄く、速度オーバーヘッドになるため不採用。

---

### パーティション・ボリューム構成（LVM採用）

**LVM（Logical Volume Manager）を採用する理由：**
- 現在1本のディスクでも、後から2本目を追加してボリュームグループを無停止で拡張できる
- 論理ボリュームのサイズをオンラインでリサイズ可能（パーティション分割の失敗を後から修正できる）
- Ubuntu インストーラが標準サポートしており、導入が容易

#### 初期構成（NVMe 2TB × 1本）

```
[ NVMe 2TB (nvme0n1) ]
├── nvme0n1p1  EFI System Partition  1 GB
├── nvme0n1p2  /boot                 2 GB    (ext4, LVM外)
└── nvme0n1p3  LVM Physical Volume   残り全て（≒1.99 TB）
       └── Volume Group: vg0
              ├── lv_root   /        100 GB  (ext4)
              ├── lv_var    /var     200 GB  (ext4)  ← Docker/ログ領域
              ├── lv_data   /data    残り全て（≒1.69 TB）  (ext4)  ← モデルファイル置き場
              └── (swap はスワップファイルで後から対応)
```

> `/boot` は LVM 外に置くことでブートローダーのトラブルを回避する。

#### 将来の拡張（NVMe 2本目追加時）

```bash
# 1. 2本目の NVMe を LVM Physical Volume として初期化
sudo pvcreate /dev/nvme1n1

# 2. 既存のボリュームグループに追加
sudo vgextend vg0 /dev/nvme1n1

# 3. /data 論理ボリュームを拡張（容量を全て /data に割り当てる例）
sudo lvextend -l +100%FREE /dev/vg0/lv_data

# 4. ファイルシステムをオンラインで拡張
sudo resize2fs /dev/vg0/lv_data
```

**追加作業はOS稼働中・無停止で実行可能。**

### スワップの方針

| 項目 | 内容 |
|---|---|
| 方式 | **スワップファイル**（`/swapfile`）をインストール後に作成 |
| サイズ | **8 GB**（メモリ 64 GB のため OOM の安全網として最小限） |
| 理由 | LVM パーティション内にスワップパーティションを作ると後から変更しにくい。スワップファイルなら柔軟にサイズ変更・削除が可能 |

> ⚠️ LLM 推論中にスワップが発生すると性能が著しく低下する。
> スワップはあくまで緊急時の安全網とし、依存しない設計にする。
> zram（Ubuntu デフォルト有効）が補助スワップとして機能するため通常は十分。

---

### データ配置とバックアップ

| 項目 | 内容 |
|---|---|
| モデルファイル置き場 | `/data/models`（`lv_data` 上）。Ollama・llama.cpp ともにパス変更可能 |
| Ollama モデルパス変更 | 環境変数 `OLLAMA_MODELS=/data/models` を設定 |
| Docker データ | `/var/lib/docker` は `lv_var` 上に収まる設計 |
| **バックアップ先** | **既存 NAS に定期バックアップ**（`rsync` + cronまたはsystemd timer） |
| バックアップ対象 | `/data/models`（モデルファイル）、設定ファイル類 |
| バックアップ頻度 | 新規モデル追加時 + 週次（要件に応じて調整） |

---

### LLM サーバー用途の固有考慮点

| 項目 | 内容 |
|---|---|
| モデルサイズの目安 | 7B GGUF Q4: 約 4 GB、70B GGUF Q4: 約 40 GB |
| Docker 利用時 | `/var/lib/docker` が肥大化しやすい。`lv_var` を 200 GB 確保することで `/` を圧迫しない |
| tmpfs | `/tmp` は OS デフォルト（tmpfs）で問題なし |
| 2 本目 NVMe | 追加時は LVM で `/data` を拡張。OS 再インストール不要 |

## 起動用USBメモリ作成（Windows 11）

### 用意するもの

- USBメモリ（8GB以上、推奨16GB以上）
- Ubuntu 24.04 LTS のISOファイル
- Rufus

### 手順

1. Ubuntu公式サイトからISOファイルをダウンロードする
2. Rufusを起動し、対象USBメモリとISOを選択する
3. パーティション構成を `GPT`、ターゲットシステムを `UEFI` に設定する
4. 書き込みを開始する（USB内データは消去される）
5. インストール対象PCでUSBブートしてUbuntuをインストールする
